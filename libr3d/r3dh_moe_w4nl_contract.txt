Only moe_gemm_q dtype=w4nl64a8i8h, a_order=sorted, parts=1, group=128,
a_group=128. M=1..2048, N positive multiple of 16, K and K_odd whole 128,
N_odd=N, n_expert=1..512, top_k=1..min(10,n_expert). N/K are bounded at 65536.
The actual TP2 down uses N=2560, K/K_odd=384/256 or 256/384, 512 experts,
top_k=10. The common activation leading dimension holds max(K,K_odd).
Protected BF16 experts, token-order activation, other quantization formats,
other architecture targets, registration, and shared-source integration are excluded.

Nine operand slots, matching arch/common/rad_block_moe_fp8.h and libref/ref_moe.cpp:
0 rotated int8 activation [M*top_k,max(K,K_odd)]
1 float32 activation scales [M*top_k,max(K,K_odd)/128]
2 even expert codes/table native table
3 even expert E4M3/scale.1 native table
4 int32 sorted_tok [M*top_k], flattened token*top_k+slot or -1
5 int32 expert_offset [n_expert+1], nondecreasing, first 0, last <= M*top_k
6 odd expert codes/table native table
7 odd expert E4M3/scale.1 native table
8 sorted BF16 output [M*top_k,N]
Activation and output matrices allow padded leading dimensions; inner stride is 1.
Sorted rows use activation row i, not sorted_tok[i]/top_k. Negative slots and
rows beyond the final offset produce zero. Empty expert spans issue no invalid grid.
The offsets are the upstream routing contract, not host-read or synchronized by launch.

Strict input encoding: affine, transform=fwht128, exactly four planes:
codes: u4 tiled [1,1], logical dense [N,K], low nibble first, rows byte-aligned.
table: float32 table extent [1,16]; selected with codes, after codes.
scale: E4M3 tiled [1,64], dense [N,K/64].
scale.1: float32 tiled [0,0], scalar or [1,1], exactly 1/8192.
Nonfinite table values and E4M3 NaN codes 0x7f/0xff are rejected at transform.
Signed/zero finite E4M3 values are preserved. No implicit scale rounding or cast to int8.
The actual model table is +/-[1.125,3.25,5.5,8,11,14,18,22], NOT an int8 grid.

Codes native layout: private dtype 0x72346e63, tag r3dh.moe.w4nl64.codes.f32table.v1.
80-byte CodesHeader {magic=0x344c4e43,version=1,N,K,float table[16]}, then N*K/2 raw bytes.
Scales native layout: private dtype 0x72346e73, tag r3dh.moe.w4nl64.e4m3.f32level.v1.
32-byte ScalesHeader {magic=0x344c4e53,version=1,N,K,float level,uint32 reserved[3]},
then N*(K/64) raw E4M3 bytes. Reserved words are zero. Both layouts align to 256 bytes.
Each layout is rank 1, shape[0]=bytes. Dtypes are opaque, not ordinary u8/fp8/i8 weights.
Native table tensors are rank 2 [entries,blob_bytes], stride[1]=1, of the private dtype.
stride[0]=0 means DEVICE pointer array, one pointer per expert entry.
stride[0]>0 is a BYTE stride for stacked blobs, >=blob_bytes and divisible by 16.
The even class has ceil(n_expert/2) entries, odd has floor(n_expert/2).
Expert e resolves class=e%2 and entry=e/2; each class uses its own K.
Logical weight shape descriptors are F32, describing table-expanded values, not the native blobs.

Launch checks descriptors, not device payload integrity. Device pointers, allocation extents,
nondecreasing offsets, and native blobs produced by successful transform are caller preconditions.
Malformed host descriptors return the exact RAD_E_INVAL/DTYPE/SHAPE/STRIDE classes; launch cannot
synchronously reject corrupted device offsets or native payloads. Out-of-range sorted slots,
inactive rows, null expert entries, and failed checked header fields produce zero output.
This is not a promise to detect every corrupt native field; transform/inverse validate payloads.
The checker initializes RadArgs by named ABI fields (TP rank, world_size=2, kv_used_max_h=-1)
and checks all four encoding constructor indices, including the actual five-argument
rad_enc_add_table(encoding, role, dtype, rows, columns) ABI.

Arithmetic is libref quant_dot, with ascending groups of 64 and ascending K inside each:
sub = float32 sequential sum of float32(float32(int8_a)*table[code]);
sb = float32(E4M3_decode(scale[n,group])*scale.1);
acc = float32(acc + float32(float32(sub*a_scale[row,group/2])*sb));
Final conversion is BF16 round-to-nearest-even, with no FMA contraction.
No CPU fallback, hidden quantization, predecoded weight cache, allocation, or host synchronization
occurs in launch. The supplied HIP stream is used directly and checked by graph capture.

Each case repeats changed inputs on a nondefault stream, with allocation and row-padding guards.
