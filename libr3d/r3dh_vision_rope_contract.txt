The aggregate preserves the existing three schemas and fifteen kernel pointers

Only the canonical fused rope launcher is registered, not the Q/K helper.

Canonical two operands, no separate output:
  qkv: BF16 [M,3456], element strides [3456,1], INOUT.
       Each row is Q[16,72], K[16,72], V[16,72], in that order.
  positions: I32 [2,M], element strides [M,1], read-only.
             Plane 0 is row; plane 1 is column.
An extra contiguous [3,M] position view is accepted; plane 2 is ignored.
F32/F16 positions, [M], [4,M], and arbitrary strides are not supported.
The schema shape hook returns [2,M], matching the actual ViT issue path.

Unregistered Q/K helper takes three operands in order: Q, K, positions.
Q and K are BF16 [M,1152], stride [1152,1] for separate allocations, or
stride [3456,1] for views into a fused row, K.data = Q.data + 1152 BF16.
Both are mutated in place; there is no output operand or copy-back fallback.
Overlapping Q/K storage is refused except the exact canonical fused views.

Required parameters:
  M: integer 1..256
  head_dim: integer 72
  n_head: integer 16
  mode: string axial
  sections: string 18 18 (two positive 18s, no trailing non-whitespace)
Optional parameters, with defaults:
  n_head_kv: integer 16
  rotary_dim: integer 72
  theta: finite F64 converted to finite positive F32, default 10000
  scale: finite F64 converted to finite positive F32, default 1
  dtype: bf16 only
  ladder: rotary only
  yarn_factor / llama3_factor: zero only
Unknown/duplicate keys, wrong parameter kinds and malformed descriptors reject.
Shape queries accept a valid M range whose high endpoint is at most 256;
launches require a resolved integer M and exactly matching active tensor rows.
Dispatch constraints require explicitly resolved n_head_kv=16, rotary_dim=72
as the actual architecture supplies both. Section validation lives in the
shape hook and launcher: RAD_C_IN tokenizes a string set and cannot represent
the multiword value 18 18. The real engine matcher is regression-tested.

Semantics verified from arch/common/rad_block_vit.h and libref/ref_attn.cpp:
  The ViT declaration sets section widths to head_dim/4 = 18 each.
  Its issue path passes a dense [2,M] row/column view of enc_coord to rope;
  the separate grid_embed issue receives [4,M] from the same buffer.
  Each head uses NeoX pairs (pair,pair+36).
  Pairs 0..17 use row, pairs 18..35 use column.
  Both sections restart the frequency ladder at theta^0.
  inv[j] = 1 / F32(pow(F64(F32(theta)), F64(F32(2*j)/F32(36)))).
  angle = (F32(position)/F32(scale))*inv[j].
  sin/cos are evaluated in double and rounded to F32, as libref does.
  Separate F32 products and sum/subtraction are rounded BF16 nearest-even.
  V storage, positions and allocation guards are unchanged.
The implementation launches native HIP asynchronously on the supplied stream;
only parameter/frequency preparation is performed on the host.
