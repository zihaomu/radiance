- **C1 feasibility decision: prototype separately, not a drop-in epilogue.** Both AR forms update the residual `w.h` in place and also write `w.x.x`; HC reads `w.h` with the *next* connection's weights and can overwrite shared activation/inject buffers. For this batch and width the AR grid is two 256-thread blocks (320 eight-element words), each responsible for half of every residual stream. HC down uses 168 blocks. A composite TP2 op would need to retain the two original peer sequence/slot owners, publish each completed half to its consumer blocks with release/acquire ordering, protect old inject values until both producers finish using them, and guarantee producer forward progress on both devices. Reusing `gridDim.x` or advancing peer counters from 168 blocks would change the protocol. Start a prototype with only the **48 plain** adjacent pairs; add gather only after the two-rank handoff is verified. Guard on exact wire, one decode row, buffer identity and graph adjacency; fall back for exact precision, intervening PLE/control-vector/debug work, checkpoints or incompatible scratch. The 47 gather pairs are further opportunities, not validated fusions. In a representative pass the unpaired write is followed by a cast, not an HC read. No combined kernel was run.

## Baseline and question

The [TP2 comparison, section 10](Qwen3.8_Flash_Next_TP2_W7900_vs_Strata.md) records 59.5 tok/s on GPU4+5 with tolerance enabled, versus 65.75 for Strata. There are 97 HC calls per token. The standalone rotating-weight benchmark measures about 21.6 us per call; Strata's profile implies 16.3 us per call. These are different measurement methods, so use the same harness for each A/B decision.

In a timestamped run of the 168-block kernel, the last block started around 3.5 us after the first. Blocks finished the down phase at 10.6-14.3 us, and the first block passed the barrier around 15.2 us. Instrumentation changes the duration. Compare timestamps from the same run; do not subtract a cold, instrumented timestamp from the 21.6 us steady-state result.

**Hypothesis:** early up-weight loads may delay some waves at the barrier. Other explanations include staggered block starts, unequal down work, and serialization at the arrival counter. Relaxed polling and separate wake words did not improve the earlier benchmark. Effective bytes per kernel time is not a measurement of peak VRAM utilization.
