## 容量诊断：两边同时给 20 GiB 专家主机池

为排除 16 GiB 下单卡没有成绩的问题，保留同一服务端、插件、权重、十个优化开关、TP exact wire、int8 KV、单流、禁用前缀缓存、预填充分块 512 和 2 GiB 显存余量。单卡只用 GPU4，双卡用 GPU4/5。两者固定 MTP0，使用同一份已哈希的 32K 请求，各四次完整预热后测两次；不把修改了池大小的单卡数字混入 16 GiB 对照。每个请求前后检查所有可见卡的实际 owner，服务端吞吐不含 prefill。[复现入口](../../../README.md#evidence)（包内：`results/tp1-tp2-32k-20261126/run.sh`）

## 如何解释

双卡并非没有收益，也不是把所有工作简单对半。等池大小下，两卡分片后，大部分专家权重可留在显存；单卡放置（历史引用，未随包保存：`results/tp1-tp2-32k-20261126/steady20-tp1-mtp0/startup.log`）仍有 16.86 GiB 专家权重在主机，命中时要过 PCIe；双卡放置（历史引用，未随包保存：`results/tp1-tp2-32k-20261126/steady20-tp2-mtp0/startup.log`）每个 rank 只有 75.95 MiB。这个数是权重存量，不是每 token 的传输量。固定 256 输出时，31.39 秒总节省中约 29.34 秒来自首 token 之前；所以整请求收益接近预填充收益，而非解码吞吐倍率。

双卡使用直接 P2P，并非通过主机中转。在更早一次同模型 32K MTP0 的[rank 0 设备轨迹](../../../README.md#evidence)（包内：`results/32k-mtp3-verify-20261125/mtp0/stamps.csv`）中，每步 97 次可辨识的两卡归约相关 kernel，执行区间并集平均 **1.92 ms**，整步轨迹跨度 **19.52 ms**（252 次完整回放；[复算](../../../README.md#evidence)（包内：`results/tp1-tp2-32k-20261126/collectives.json`））。其中有融合的 HC 写回，不是纯通信耗时，也不能从本次无插桩速度中直接扣除。此次没有实测 PCIe 流量或两端关键路径，不能将未达到线性加速的部分全归咎于通信。

若要比较 **MTP3** 的拓扑收益，先补 TP1 必经的[全词表 rerank 声明](../../../../../arch/common/rad_block_mtp_hc.h#L420)及实际可运行的内核，逐一确认其余未解析形状是否必需，再在能加载的相同主机池配置下复测。当前没有 TP1/MTP3 的 32K tok/s。
